OIA Backend — Complete Architecture Diagrams

Bennett University — Office of International Affairs Student Portal
Verified against codebase on 2026-07-18 | Express.js + Prisma + Supabase + Cloudflare R2

1. Request Lifecycle (Middleware Pipeline)

Every incoming HTTP request passes through this pipeline before reaching any controller:

flowchart TD
    REQ([Incoming HTTP Request]) --> HELMET[helmet: Security Headers]
    HELMET --> RATE[express-rate-limit\n100 req/15min prod]
    RATE -->|Exceeded| R429([429 Too Many Requests])
    RATE -->|OK| CORS[CORS Check]
    CORS -->|Blocked| RCORS([CORS Error])
    CORS -->|OK| PARSE[express.json + cookieParser]
    PARSE --> ROUTER{Route Matched?}
    ROUTER -->|No| R404([404 NOT_FOUND])
    ROUTER -->|Yes| AUTH{Requires Auth?}
    AUTH -->|No| CTRL[Controller Logic]
    AUTH -->|Yes| A1

    A1[Extract token from\ncookie or Bearer header] --> A2{Token found?}
    A2 -->|No| A401([401 UNAUTHORIZED])
    A2 -->|Yes| A3[jwt.verify SUPABASE_JWT_SECRET]
    A3 -->|Valid| A5[Decoded payload]
    A3 -->|Invalid| A4[Fallback: supabase.auth.getUser]
    A4 -->|Fail| A401
    A4 -->|OK| A5
    A5 --> A6{Email @bennett.edu.in?}
    A6 -->|No| A403([403 FORBIDDEN])
    A6 -->|Yes| A7[Assign role via regex]
    A7 --> A8[prisma.users.upsert - JIT]
    A8 --> A12[req.user = appUser]
    A12 --> ROLE{Requires Role?}
    ROLE -->|No| CTRL
    ROLE -->|Yes| R1{Role authorized?}
    R1 -->|No| R403([403 Insufficient role])
    R1 -->|Yes| CTRL
    CTRL --> ZOD{Zod Validation}
    ZOD -->|Fail| ZERR([400 VALIDATION_ERROR])
    ZOD -->|Pass| RESP([Business Logic + Response])

2. Review and Approval Workflow

Programs, Events, MOUs, and Visits share this pattern. Admin/Editor writes are intercepted into a review queue.

flowchart TD
    REQ([Create / Update / Delete]) --> ROLE{User Role?}
    ROLE -->|super_admin| DIRECT[Direct DB Write]
    DIRECT --> AUDIT[audit_logs entry]
    AUDIT --> CACHE[invalidateCache]
    CACHE --> RES201([201/200 Response])

    ROLE -->|admin / editor| REVIEW[Create Review Record]
    REVIEW --> RDATA[reviews.data JSON:\naction, targetId, payload]
    RDATA --> RES202([202 Accepted + reviewId])

    RES202 -.-> APPROVE{Super Admin Decision}
    APPROVE -->|Approve| APPLY[Apply payload to target table\nSet status: published]
    APPLY --> ALOG[audit_logs: Approved]
    APPROVE -->|Reject| REJECT[status: rejected]
    REJECT --> RLOG[audit_logs: Rejected]
    APPROVE -->|Changes| CHANGES[Append comment\nstatus: changes_requested]
    CHANGES --> CLOG[audit_logs: Requested_Changes]

4. Data Flow: Storage and Caching

flowchart TD
    subgraph READ [Read Path]
        R1[Read Request] --> R2{Cache hit?}
        R2 -->|Hit| R3([Return cached])
        R2 -->|Miss| R4[(PostgreSQL via Prisma)]
        R4 --> R5[setCached 60s TTL]
        R5 --> R6([JSON Response])
    end

    subgraph WRITE [Write Path]
        W1[Write Request] --> W2[Zod validate]
        W2 --> W3[(PostgreSQL Write)]
        W3 --> W4[(audit_logs)]
        W4 --> W5[invalidateCache]
        W5 --> W6([JSON Response])
    end

    subgraph FILES [File Operations]
        F1[Upload: multer] --> F2[R2 PutObjectCommand]

        F4[Download] --> F5[getSignedUrl 15min]
        F5 --> F6([Pre-signed URL])
        F7[Media Proxy] --> F8[Stream from R2\nCache-Control: 1 year]
    end

5. User Deletion Transaction

The most complex operation — a single Prisma transaction handling cascading cleanup:

flowchart TD
    DEL([DELETE /users/:id]) --> FIND{User exists?}
    FIND -->|No| R404([404 NOT_FOUND])
    FIND -->|Yes| T1[Find fallback admin]

    T1 --> T2{Fallback found?}
    T2 -->|Yes| REASSIGN[Reassign ownership:\nprograms, events, mous,\nvisits, reviews]
    T2 -->|No| CASCADE[Cascade delete all\nowned resources]
    REASSIGN --> UNLINK[Unlink POC refs → null]
    CASCADE --> UNLINK
    UNLINK --> DELAPPS[Delete applications]
    DELAPPS --> DELSTUD[Delete student record]
    DELSTUD --> DELUSER[Delete user]
    DELUSER --> R200([200 Deleted])
